# Implementation notes

The project was initialized as a nested Git repository at `/home/jafed/App/MiCampus`; the sibling `REFERENCE` repository was inspected read-only and was never modified. No commit is created by this implementation.

## Architecture and persistence

- One `:app` module keeps domain models in `core.model`, state and Compose UI in `feature.*`, persistence in `data.local`, institutional data in `data.institution`, import engines in `data.document`/`data.ai`, and Android integrations in `platform.*`.
- Immutable `StateFlow` screen states drive Compose. `NavigationSuiteScaffold` changes navigation presentation with window width, while Calendario uses side-by-side month/agenda content at 840dp and above.
- Room version 11 stores confirmed events, editable drafts, external calendar records, retained-document metadata, processing attempts, and local document-chat transcription chunks. Explicit migrations through 10→11 preserve existing data. Retained PDF bytes live only under `noBackupFilesDir/imported_pdfs`; transcription rows are excluded from backup with the Room database and are deleted with their source PDF.
- DataStore persists onboarding, selected institutions, theme, reminder options, and independent `ai_local`/`ai_cloud` preferences. On upgrade, each missing new key falls back independently to the legacy `ai` value; fresh installations default both to `false`.

## Transport resolution

- Versioned UCR/UNA JSON assets carry their official source URL, verification range, stops, notes, weekday/Saturday trips, inclusions/exclusions, and the UCR intermediate-term override.
- A date must first be inside the verified range. The UCR weekday override is inclusive from 2026-07-13 through 2026-08-07; Saturdays in that interval continue to use the regular Saturday timetable. Explicit exclusions suppress service and inclusions enable weekday departures. The resolver searches bounded future dates for the next verified service day.
- Expired or unknown data never produces a countdown. Academic calendar data remains pending and no entries are invented.

## PDF and AI pipeline

- SAF can supply up to 10 read-only PDF URIs per batch (25 MiB each, 100 MiB total). Originals are copied atomically into content-addressed app-private storage before parsing; identical bytes reuse one local copy while each run gets its own attempt record. On API 35+, `PdfRenderer.Page.textContents` is used directly. Empty pages are rendered within a pixel bound and processed by the bundled Latin ML Kit recognizer. Page numbers and source-document provenance survive normalization and overlapping token-safe chunking.
- The chunker budgets the final page-labelled prompt at 2,400 words with 120-word overlap. Gemini Nano retrieves the runtime token limit before counting the complete instruction plus document chunk, requires fewer than 4,000 input tokens, reserves 2,048 output tokens, and recursively splits oversized page-aware local prompts. If an unexpected full-request token-count failure occurs, a constant tiny count distinguishes oversized input from an SDK/AICore failure without inspecting or retaining document content.
- Selectable, scanned, tabular, OCR-error, and empty-document paths are covered by JVM coordinator tests. Malformed and password-protected fixtures exercise the Android `PdfRenderer` adapter in the API 26/35 device job; permission denial is also represented by a distinct typed failure.
- Ajustes exposes independent **Modelo local (Gemini Nano)** and **API de Google Gemini (nube)** switches. The local switch is visibly disabled while capability is checking, unavailable, or failed, while `AVAILABLE`, `DOWNLOADABLE`, and `DOWNLOADING` are compatible states. Its stored preference is retained across temporary AICore failures. The cloud key controls are disabled—but the encrypted key is not deleted—when cloud AI is off.
- Import routing reads both preferences independently: local-compatible/local-on tries Nano first; cloud-on may request explicit batch consent after local failure; cloud-off always continues manually after local failure; local-off or unavailable skips Nano. Successful local extraction makes no cloud request, and cloud actions are absent when cloud AI is disabled.
- `EventExtractionEngine` checks Gemini Nano capability (`AVAILABLE`, `DOWNLOADABLE`, `DOWNLOADING`, or `UNAVAILABLE`) and requires explicit confirmation before model download. Download progress and failures are typed. Busy generation retries after 500 ms, 1 s, and 2 s; background, battery quota, storage, compatibility, system-update, policy/request, response, and SDK failures map to actionable Spanish UI. Coroutine cancellation is preserved. Explicit retry recreates the ML Kit client after SDK/unknown failures.
- ML Kit Prompt `1.0.0-beta2` supports local status/download/generation in this build. Generation uses one candidate, temperature 0, seed 7, and 2,048 maximum output tokens. The pinned beta2 request builder exposes no thinking-control property, so Mi Campus requests direct JSON with no reasoning text instead of pretending to configure an unavailable API. The model warms once, exposes its base-model identifier for diagnostics, and is closed with its owning ViewModel. The published beta2 artifact also does not expose the alpha structured-output API, so generation uses a strict JSON-only prompt followed by defensive Kotlin/Gson validation; only whitespace or one surrounding JSON fence is accepted.
- Device support, base-model identity, download state, and token limit are read from ML Kit at runtime; no manufacturer, phone model, or Nano generation is hardcoded. The model is not bundled: first download needs network, storage, and user confirmation. Inference is foreground-only; leaving the importer cancels the active request while preserving the batch and offers **Reintentar en el dispositivo** after resume. No new permissions, analytics, LiteRT runtime, or separately downloaded model are added.
- Debug builds retain a fixed-schema, redacted trace for the latest 10 import attempts or explicit Nano self-tests under `noBackupFilesDir/diagnostics`. It records effective AI switches, operation names, numeric input sizes, allowlisted exception categories, ML Kit error codes, Nano status/model/token limits/splits/failures, foreground interruption, consent decisions, cloud models/retries/HTTP statuses, and the final backend. It has no free-form message/content field, and release resolves the same interface to a no-op. Ajustes can run a constant content-free Nano test and share a ZIP (`summary.txt`, `events.jsonl`, `privacy.txt`) through the existing `FileProvider`; generated archives remain local and are replaced on the next export.
- Cloud requests prefer `responseMimeType: application/json` with a nullable JSON Schema. If an endpoint rejects that option, the same model retries with a strict JSON-only prompt and still validates in Kotlin. A batch-scoped session starts with stable `gemini-3.5-flash`, retries transient failures once with bounded jitter/backoff, then advances to `gemini-3.1-flash-lite` and `gemini-2.5-flash`; a successful fallback remains selected for later chunks in the batch. Requests send extracted text, never PDF bytes, use the `x-goog-api-key` header, bounded timeouts/responses, and typed invalid-key, quota, offline, server, and invalid-response failures. Keys use Android Keystore AES-GCM; ciphertext is atomically stored in `noBackupFilesDir`.
- Missing or ambiguous values stay nullable and are marked. Dates, time ranges, institutions, inferred years, and duplicates are validated in Kotlin. All generated results remain editable drafts until the student explicitly confirms each one; neither local nor cloud output writes directly to Android Calendar.

## Calendar and reminders

- Calendar read/write permissions are requested only from the export action. A SHA-256 content hash plus `(eventId, calendarId)` record makes export idempotent: unchanged events are skipped, changes require confirmation, and external events are never automatically deleted.
- Timed events default to 24-hour and 1-hour reminders; all-day events default to 24 hours. Past triggers are skipped. Exact alarms are used only when requested and authorized, otherwise unique WorkManager jobs provide inexact delivery. Notification/exact-alarm access is requested only when enabled in Ajustes. Boot, clock, timezone, and exact-alarm-access changes reschedule future reminders.

## Verification environment

This Codex host does not provide a system JDK/AAPT2, so verification uses a temporary Nix JDK 17 and AAPT2 without modifying the machine. The equivalent local command is:

```bash
nix-shell -p jdk17 aapt --run 'ANDROID_HOME=/home/jafed/Android/Sdk ./gradlew -Pandroid.aapt2FromMavenOverride=$(command -v aapt2) lint testDebugUnitTest assembleDebug'
```

Compose instrumentation includes compatible, downloadable, unavailable, dark-theme, and large-font Settings smoke states. The opt-in device test trusts runtime capability, skips unsupported devices, does not download a model, accepts any non-empty base-model identifier, and performs a foreground self-test only when Nano is already installed. Execution is delegated to emulator/device jobs when no device is attached.
